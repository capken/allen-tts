# 合成用法

## 基本命令

```
allen-tts speak -p <服务商> -v @default --json "<文本>" -o <输出路径>
```

- **总是加 `--json`**：标准输出会是一个 JSON，包含 `output`（绝对路径）、`format`、
  `duration_ms`、`usage`、`warnings` 等。
- `-o` 省略时会自动命名成 `./tts-<时间戳>.<扩展名>`。建议显式指定一个有意义的文件名。
- `--json` 和 `-o -`（输出到标准输出）互斥，同时用会报参数错误。
- 文本很长时不要塞进命令行，写进文件后用 `--text-file <路径>`，或从标准输入管道传入。

## 把用户的要求翻译成参数

| 用户说 | 参数 | 范围 |
|---|---|---|
| 快一点 / 慢一点 | `--speed` | 倍数 0.5–2.0，默认 1.0 |
| 大声 / 小声 | `--volume` | 倍数 0.5–2.0，默认 1.0 |
| 音调高 / 低 | `--pitch` | 半音 -12–12，默认 0 |
| 开心 / 难过 / 生气… | `--emotion` | neutral、happy、sad、angry、fearful、surprised、calm、excited |
| 用英文 / 粤语念 | `--lang` | BCP-47，如 en、zh、yue |
| 要 wav / 无损 | `--format` | mp3、wav、pcm、opus、flac |

拿不准某家支不支持某个参数时，先查：`allen-tts capabilities -p <服务商>`。

## 三家能力差异

| 能力 | minimax | fish | cartesia |
|---|---|---|---|
| 音调 pitch | 支持 | 不支持 | 不支持 |
| 情绪 emotion | 支持 | 不支持 | 支持 |
| 语言 lang | 支持 | 不支持 | 支持 |
| 流式 | 支持 | 支持 | 不支持，自动退化为非流式 |
| 格式 | 五种全支持 | 除 flac | 仅 mp3/wav/pcm |
| 返回时长和用量 | 有 | 无 | 无 |

不支持的参数默认会被丢弃并写进 `warnings`，**必须把这些 warning 转述给用户**，
否则他们会以为设置生效了。别的处理方式：加 `--on-unsupported=error` 让它直接报错，
或 `--on-unsupported=drop` 静默丢弃——除非用户明确要求，否则保持默认。

**格式不支持是永远报错的**，不会静默换成别的格式。这是有意为之：静默替换会让文件内容
和扩展名对不上。遇到就换格式或换服务商。

## 长文本

超过大约 3000 字时加 `--stream`，边收边写，避免长时间没有任何输出。

minimax 对单次请求有 10000 字硬限制，超了会直接报 `invalid_text`。这种情况必须先分段
（按段落或句子切，不要从中间截断），逐段合成后再交付多个文件，或告诉用户需要合并。
命令行工具本身不做音频拼接。

## 厂商特有能力

统一参数覆盖不到的厂商特性，用 `--extra` 传原始 JSON，它会深合并进厂商请求体，不做校验。
例如给 fish 调采样温度：`--extra '{"temperature":0.9}'`。

## 交付

把 JSON 里 `output` 的绝对路径告诉用户。如果 `duration_ms` 有值，一并说一下时长。
有 `warnings` 就如实列出来。
